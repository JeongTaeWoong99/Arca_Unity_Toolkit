# 스킬 마스터 원본

> 최종 업데이트: 2026-09-20 (`github-issue-writer` 추가 · `unity-handoff` → `unity-editor-ops` 개편)

`/unity-project-setup`이 새 프로젝트의 `.claude/skills/`로 복사하는 스킬의 단일 진실.
프로젝트에서 다듬은 **범용 개선**은 `/unity-skill-sync`로 여기 되돌린다.

---

## ⚠️ 이 스킬들은 공동 소유다

여기 있는 스킬은 **여러 프로젝트에 심기고, 여러 사람이 각자의 프로젝트에서 고친다.**
그래서 마스터와 사본은 **양방향으로 어긋날 수 있다.** 한쪽을 일방적으로 덮으면
남의 개선이 조용히 사라진다.

그래서 각 `SKILL.md` 상단에 소유 표식을 둔다.

```markdown
> 🔗 **공동 소유** — Arca Unity Toolkit 마스터가 원본이고, 여러 프로젝트·여러 사람이 함께 쓴다.
>   이 사본을 고쳤으면 `/unity-skill-sync`로 되돌리되, **마스터 반영 여부는 사용자에게 확인받는다.**
>   프로젝트 고유 경로·고유명사가 섞인 수정은 마스터로 올리지 않는다.
```

### ⛔ 이 표식은 **마스터에만** 둔다

프로젝트 저장소로 복사할 때는 **떼어 낸다.** 프로젝트의 `.claude/skills/`는 **협업자와 함께 쓰는
파일**이라, 내 개인 툴킷 사정을 적어 두면 그 사람에게는 뜻 모를 문구가 되고
"이건 내가 건드리면 안 되나?"라는 오해만 만든다.

- `/unity-project-setup` — 복사할 때 블록을 **지운다.**
- `/unity-skill-sync` — 이 블록을 **차이로 치지 않는다.** push 할 때 붙이고 pull 할 때 뗀다.

**안전장치는 마스터와 sync 절차에서만 건다.** 그것으로 충분하다.

**프로젝트 사본을 직접 고치는 것은 허용한다.** 막는 것은 되돌림을 건너뛰는 것뿐이다.

## 지금 있는 것

| 그룹 | 스킬 | 원작 |
|------|------|------|
| `client/` | `clean-code-style` · `feature-design` · `optimization` · `unity-editor-ops` | 본인 |
| `client/` | `ugui-layout` · `ugui-mvp` | 본인 (DesktopWindow_Control에서 승격, 2026-08-26) |
| `common/` | `commit-convention` | 본인 |
| `common/` | `github-issue-writer` | 본인 (DesktopWindow_Control에서 승격, 2026-09-20) |
| `common/` | `agent-log-writer` · `agent-log-reader` · `task-writer` · `task-reader` | **서버 담당 동료** (DesktopWindow_Control, 2026-08-26 범용화 후 승격) |
| `server/` | (없음) | — |

> **원작을 적어 두는 이유** — "이 규칙 왜 이래?"를 물을 곳을 알기 위해서다.
> 남이 쓴 스킬을 범용화할 때는 **의도를 지우지 않았는지** 특히 조심한다.

### ⚠️ `common/` 4종은 원본 프로젝트와 내용이 다르다 (정상)

`agent-log-*`·`task-*`는 DesktopWindow_Control에서 가져오면서 그 프로젝트의 예시
(엑셀 파이프라인 · 패킷 · DB 컬럼 · 특정 ID 이설)를 **중립 예시로 바꾸고**,
"1인 개발이면 `담당` 필드를 두지 않는다" 분기를 더했다.

**원본 프로젝트의 사본은 손대지 않았다** — 거기서는 서버 담당 동료가 계속 쓰는 파일이다.
그래서 그 프로젝트와 sync를 돌리면 이 4종은 **항상 차이로 잡힌다. 그게 정상이고, push 하지 않는다.**
다른 프로젝트에서는 마스터 판(범용화된 쪽)을 그대로 쓴다.

## 마스터에 없는 것 — 프로젝트 특화

`excel-table-creator`·`game-design-reference`(DesktopWindow_Control)는 `GameDesign/Excel` 파이프라인과
기획 문서 경로에 결합돼 있어, 그것을 걷어내면 **남는 게 껍데기다.** 그래서 올리지 않았다.

**프로젝트 특화 판정은 내용으로 한다** — 고유 경로·기획 문서 이름·서버 스펙을 걷어냈을 때
남는 게 있는지를 본다. 표식 같은 것으로 표시하지 않는다.

## 마스터 스킬의 불변 규칙

- **프로젝트 고유명사·경로를 남기지 않는다.** 클래스 이름은 `XxxManager`·`XxxModel` 같은
  자리 표시자로, 경로는 저장소 루트 기준으로 적는다.
  (실제로 `MonoService`의 예시가 `SessionManager`로 굳어 있다가 그 클래스가 사라진 적이 있다)
- **`description`은 발동 조건의 명세다.** 내용 요약이 아니다 —
  "**언제 적용하는가**"와 "**언제 적용하지 않는가**"를 함께 적는다.
  이게 곧 스킬이 열리는 조건이므로, 넓게 쓰면 관계없는 작업마다 문서를 통째로 읽는 비용을 문다.
- **"필독·반드시·항상·모든"을 쓸 때는 그것이 정말 예외 없는지 확인한다.**
  조건이 있으면 조건을 적고, **읽지 않아도 되는 경우를 함께 명시한다.**
  강한 단어 한 줄이 "필요할 때만"이라는 완화 문장을 덮어쓴다.
- **한 스킬이 커지면 상세 문서로 가른다.** 같은 폴더의 `<주제> 상세.md`로 내리고
  `SKILL.md`에는 링크와 한 줄 요약만 남긴다(`clean-code-style/스타일 상세.md`가 그 예).
  ⚠️ sync는 `SKILL.md`만이 아니라 **폴더 안 모든 `.md`**를 비교한다.
- 모든 md 상단의 `> 최종 업데이트: YYYY-MM-DD`를 수정할 때마다 갱신한다.

## 그룹은 무엇으로 가르나

| 그룹 | 언제 열리나 |
|------|------------|
| `common/` | 프로젝트 영역과 무관하게 걸리는 것 (커밋 · 일감 · 작업 로그) |
| `client/` | 유니티 클라이언트 코드를 만질 때 |
| `server/` | 서버 코드를 만질 때. 서버 파트가 없는 프로젝트에는 복사하지 않는다 |

`common/`은 **클라·서버 어느 쪽에서 열려도 말이 되어야 한다.** 한쪽 색채가 강한 예시가
들어 있으면 범용화 대상이다.
